### 0.2 强制约束（PRD 红线）

- **逐一排查、不跳过**：A / B / C 三个子项各自独立排查、独立定义、独立验收；禁止"应该没问题"的批量假设。每个子项须先有「现状定位」（见 0.1）再定义修复。
- **零回归优先**：任何修改不得破坏现有 **117 个 gtest 用例**；新增行为须有新增测试覆盖。
- **最小变更**：优先在现有模型 / 函数上修补，避免大规模重构；确需模型扩展须以**最小新增字段**形式落地，并同步到所有消费方。

## A. 和弦逐音八度点位校准

### A.1 需求描述
确认并修复：`renderJianpuNote`（L1 文本）与 `jianpuToStaff`（G1 五线谱）在「和弦逐音八度点」上的处理**一致且正确**——同一 `JianpuDoc` 经两端输出，各成员音的 `octaveDots` 不应错位或丢失。

### A.2 现状根因（必须先读）
和弦的逐音八度点在**数据模型层缺失**：`chordDegrees` 仅存音级（1-7），无逐音 `octaveDots`。当前事实：
- 构造 `[1' 3,]`（根音升八度、三音降八度）**无法表达**：模型无承载字段。
- 渲染端 `renderJianpuNote` 把根音的 `octaveDots` 渲染在整组和弦括号之后，等价于"整组和弦共用根音八度"。
- 反向端 `jianpuToStaff::chordMemberPitch` 成员音固定取"相对根音上方最近"八度，丢失任何逐音偏移。

> **结论**：A 的修复**必然涉及最小模型扩展**（见风险 R1），否则"逐音八度点"需求在物理上无法满足。

### A.3 验收标准（Acceptance Criteria）

| 编号 | 验收标准 | 可检验定义 |
| --- | --- | --- |
| **AC-A1** | 可表达 | 模型须能承载和弦逐音八度点（最小方案：新增 `std::vector<int> chordOctaveDots` 与 `chordDegrees` 一一对应；或等价 `ChordMember{degree, octaveDots}` 结构）。可构造含 ≥2 成员、且成员 `octaveDots` 互异的和弦（如 `[1' 3,]`）。 |
| **AC-A2** | 渲染一致 | 对上述 `JianpuDoc` 调 `renderJianpuNote`：根音 `'` 仅作用于根音数字、三音 `,` 仅作用于三音数字，**不得**整体套用到整组和弦或错位 / 丢失。 |
| **AC-A3** | 反向守恒 | 同一 `JianpuDoc` → `jianpuToStaff` 得 `Score` →（如经 `scoreToMusicXML` 再解析）回得 `JianpuDoc'`；对每个和弦，逐成员 `octaveDots` 与原始**逐项相等**（逐音守恒），无错位、无丢失、无被"最近邻"默默改写。 |
| **AC-A4** | L2 渲染一致 | `jianpuToL2`（HTML）对逐音八度点的投影须与 L1 语义一致（逐音上 / 下点不串位）。 |
| **AC-A5** | 校验器对齐 | `verify_jianpu_groundtruth.py` 在校验和弦时，对逐音 `octaveDots` 做比对（ChordMember 维度），与 `chordDegrees` 比对并列；不引入新的 counted 缺陷。 |
| **AC-A6** | 零回归 | 新增字段 / 分支不得改变现有单音（非和弦）八度点行为；现有 117 个 gtest 用例全绿。 |

## B. tieStop 反向还原逻辑修正

### B.1 需求描述
修正 `jianpuToStaff`（G1）对连音 tie 的 stop 端还原逻辑，确保往返（`jianpu→staff→jianpu` 与 `staff→jianpu→staff` / 经 MusicXML）**音高与时值守恒、连音起止标记正确**。

### B.2 现状根因（必须先读）
- 模型仅 `tieToNext`(bool)，无"本音是被延续的 stop 端"字段。
- `staffToJianpu`(L2:176) 只写 `jn.tieToNext = n.tieStart`，**忽略 `n.tieStop`**。
- `jianpuToStaff`(G1:84-85) 恒置 `n.tieStop = false`（注释明示为已知限制）。
- **后果**：`staff → jianpu → staff` 往返后，原始 tie 的 stop 端音符（第二音）丢失延续标记，MusicXML 中连音弧变为"起而不止"，音乐语义错误。
- `verify` 脚本(L336-339) 只比对 `tie == "start"`，**不校验 stop 端**，故当前 117 个 gtest 用例未暴露该缺陷（隐蔽回归）。

### B.3 验收标准（Acceptance Criteria）

| 编号 | 验收标准 | 可检验定义 |
| --- | --- | --- |
| **AC-B1** | 模型可表达 stop 端 | 模型新增最小字段（建议 `bool tieFromPrev`，与 `tieToNext` 对称）表达"本音是连音的 stop 端"。`staffToJianpu` 据 `n.tieStop` 写入；`jianpuToStaff` 据 `jn.tieFromPrev` 设置 `n.tieStop`。 |
| **AC-B2** | staff→jianpu→staff 守恒 | 用含 tie（start+stop 配对）的 MusicXML 样本做 `staffToJianpu → jianpuToStaff`（或经 `scoreToMusicXML` 往返）：还原 `Score` 中各音符 `tieStart` / `tieStop` 起止端与原始**逐项一致**，stop 端不再被吞掉、也不再被误加。 |
| **AC-B3** | jianpu→staff→jianpu 守恒 | 含 `tieToNext` / `tieFromPrev` 的 `JianpuDoc` 往返后，连音起止标记一致；时值（quarterLength / type / dots）**不被错误拆分或合并**，tie 不被拆成两个独立音或合并为一个音。 |
| **AC-B4** | 校验器补全 | `verify` 脚本新增对 tie stop 端的校验（ground-truth `tie=="stop"` 时，转换器侧对应音符须标记为"被延续"），使该缺陷可被自动发现，而非依赖人工。 |
| **AC-B5** | 零回归 | 修复不影响无 tie / 仅单端 tie 的样本；现有 117 个 gtest 用例全绿；新增 tie 往返用例覆盖。 |

## C. 极端连音比例共 46 处容错加固

### C.1 需求描述
排查 `verify` 统计的 **46 处** `rhythm_unresolvable`（来自 7:8 / 7:4 / 9:4 极端连音比，两侧均无法映射标准简谱时值）在 converter 与 verifier 中的处理路径，做容错加固：**不崩溃、输出稳定、对未可解析时值有明确报告**，而非追求完美映射。

### C.2 现状根因（必须先读）
- converter 路径（L2:159-172）：`rhythmQl = quarterLength × tupletActual/tupletNormal`；`quarterLengthToRhythm` 失败（极端比）则回退 `typeToDuration(n.type)`。**当前已不崩溃、产出合法**，但属**静默回退**——产物无"此处时值未解析"的显式标记，下游 / 校验器无法区分"正常音"与"回退音"。
- `quarterLengthToRhythm`(L2:88-98) 与 `typeToDuration`(L2:72-81) 均有安全默认，数学上不会抛异常 / 越界。
- verifier 路径：`rhythm_unresolvable` 已单列（UNVALIDATED，不计入通过率分母），46 处可通过报告查看；**但 converter 侧无对应机读标记**，两端"未解析"口径未对齐。

### C.3 验收标准（Acceptance Criteria）

| 编号 | 验收标准 | 可检验定义 |
| --- | --- | --- |
| **AC-C1** | 不崩溃 | 对含 7:8 / 7:4 / 9:4 极端连音比的样例，`Pudu.exe` 进程退出码为 0，不抛异常、不触发断言。 |
| **AC-C2** | 产物合法 | converter 对极端比音符产出**合法且可被本仓库解析器读回**的 MusicXML / L1 / L2 / JSON，不产出非法结构（如负 duration、超界 type）。 |
| **AC-C3** | 不污染邻居 | 极端比音符的回退处理**逐音独立**，不得改变相邻音符的音高 / 节奏 / 时值（用含极端比 + 常规音符的混合样本验证）。 |
| **AC-C4** | 明确报告 | converter 对未可解析时值提供**机读标记**（最小方案：JSON 输出音级增加 `"rhythmUnresolvable": true`，或在日志 / 返回统计中计列），使下游 / verifier 能明确报告"该处时值未映射"，而非伪装为正常音。 |
| **AC-C5** | 校验口径稳定 | `verify` 脚本仍将这 46 处（实现时运行确认精确计数）单列 `rhythm_unresolvable`，**不计入通过率分母**；整体音符 / 字段通过率口径与现状一致，加固不引入新的 counted 缺陷。 |
| **AC-C6** | 零回归 | 加固后现有 117 个 gtest 用例全绿；新增"极端连音比样本 + 明确报告"的回归用例，固化"不崩溃 / 不污染 / 可报告"行为。 |

## 2. 风险与待确认问题

- **R1（模型容量 · A）**：和弦逐音八度点当前模型不可表达，A 必须最小扩展模型（`chordOctaveDots` 或 `ChordMember`）。需架构师确认最小方案，且 L1 / L2 / G1 / parse 四处同步。
- **R2（字段充足 · B）**：仅 `tieToNext` 不足以表达 stop 端，需新增 `tieFromPrev`（或等价）。需确认与 MusicXML `tie type="stop"` 的精确映射（连续多音 tie 链：start → continue → stop 的处理）。
- **R3（46 处计数）**：精确"46"以运行 `verify_jianpu_groundtruth.py` 产出的 `jianpu_groundtruth_report.json` 为准；实现时应复跑确认（可能因样本集变动而浮动）。
- **R4（明确报告口径 · C）**："明确报告"采用 JSON 字段 vs 日志统计需与架构师 / QA 对齐；建议 JSON 字段（机读、可聚合）。
- **R5（抽样人工核对）**：46 处极端连音比是否需抽样人工核对其"回退记谱"在乐理上可接受（非完美映射，但应可演奏 / 可读），建议抽 3–5 处人工确认。
- **R6（parse 端对称 · A）**：`jianpu_text_parser` 解析 `[1' 3,]` 文本时是否也需支持逐音八度点（与渲染 / 反向对称），需确认是否纳入本增量范围或留待后续。
- **R7（round-trip 粒度）**：A / B 的"往返守恒"以 `scoreToMusicXML` → 重解析为准，还是仅内存 `Score` 比较？建议两者都覆盖，以暴露序列化丢失。
